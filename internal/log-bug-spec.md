# /loop-debug --log-bug — Log a bug into a loop-runnable spec

## Problem

When a loop run misbehaves (e.g. "frozen at Phase B Step 5"), the evidence lives in the
session's custom events. Today, capturing that evidence for a follow-up fix requires
running `scripts/extract-session.sh`, manually assembling a markdown file, and writing
the bug description by hand. The script also has a hardcoded session directory
(`$HOME/.pi/agent/sessions/--Users-alancapps-...--`) that only works on one machine,
and it can only read session *files on disk* — not the live in-process session.

## Goal

Add a `--log-bug <name>` flag to the existing `/loop-debug` command. It extracts the
relevant `loop-*` events from the **current session in-process**, and writes a
self-contained `bug-fix-<slug>.md` file into `ctx.cwd` that can be fed straight back
into the loop:

```
/loop-debug --log-bug frozen-at-phase-b-step-5
→ writes bug-fix-frozen-at-phase-b-step-5.md
→ user/agent fills in problem + fix sections (or completes them mid-conversation)
→ /loop bug-fix-frozen-at-phase-b-step-5.md
```

The flag takes the **cute name of the bug the user is observing**. It is a flag on an
existing command — no new command is introduced.

## Command form

```
/loop-debug                          # unchanged: show last 20 debug entries
/loop-debug --log-bug <name>         # log-bug mode
/loop-debug --log-bug=<name>         # same, equals form (parseLoopArgs precedent)
```

- `<name>` is free text; whitespace and case are allowed ("Frozen at Phase B Step 5").
- Slugification for the filename: lowercase, replace runs of non-alphanumeric with
  `-`, trim leading/trailing `-`. → `bug-fix-frozen-at-phase-b-step-5.md`
- The file title keeps the name as given (human-readable).
- `--log-bug` with an empty/missing name → usage notify, no file written.
- If `--log-bug` is absent, the handler behaves exactly as today (args ignored).
  Unknown other flags are out of scope — do not build a general flag parser here.

## Output file

Written to `path.join(ctx.cwd, "bug-fix-" + slug + ".md")`. If the file already exists,
notify an error and write nothing (a collision means this bug was already logged —
never clobber it).

On success, notify: the written path plus the next step (`/loop bug-fix-<slug>.md`).

### File shape

The file must be a good Phase 0 input: a behavior spec, self-contained (log excerpt
inlined, not referenced from the session), with a clear target state.

```markdown
# Bug: <name as given>

> Generated by `/loop-debug --log-bug` on <ISO-8601 timestamp>.
> Resolve with: `/loop bug-fix-<slug>.md`

## Context

- Logged while loop state was: phase=<phase>, round=<round>, spec=<specPath>, language=<language>
  (or "no active loop" when state.current.phase is "idle")

## Observed problem

<one or more lines: what the user is seeing. Placeholder prompt if left unfilled:>
Describe the misbehavior (expected vs. actual, where it occurs).

## Proposed fix

<placeholder prompt if left unfilled:
Describe the fix approach you want the Writer to take.>

## Log excerpt

[<ts>] [loop-state] phase=B round=5
[<ts>] [loop-event/gate-fail] Gate failed: ...
...

## Acceptance

- The observed problem no longer reproduces (state the reproduction scenario above it).
- <specific, fill in>
```

The command writes the **structural** content: title, Context (from `state.current`),
Log excerpt (auto-extracted), and placeholder prompts for Observed problem / Proposed
fix / Acceptance. Filling those in is a human/agent step, not a command step.
Deliberately, Phase 0 will flag empty sections as underspecified — the existing
review gate is the enforcement, no new mechanism needed.

### Edge cases

- **No loop events in session** (e.g. logging a bug from before the current session):
  file is still written; Log excerpt section contains the line
  `(no loop events found in this session)`.
- **Loop idle/cancelled**: works fine; Context reads "no active loop" (state is
  still in memory for the session). The flag must not require an active loop.

## Log extraction

Source: `ctx.sessionManager.getEntries()` — the current session only. This is the
in-process equivalent of `scripts/extract-session.sh`, and supersedes it for the live
session. The bash script stays for **past session files on disk** (it takes an
arbitrary file path; the command cannot). Do not delete or rewrite the script in
this change.

- **Filter:** `entry.type === "custom"` and `customType` in:
  `loop-debug`, `loop-event`, `loop-state`, `loop-refusal`, `loop-dispute`,
  `loop-negotiate`, `loop-gate`.
- **Field access:** payload lives under `entry.data` (confirmed by the session
  JSONL shape and by `test/extension.test.ts` mocks). Read `ts`, `category`, `msg`,
  `phase`, `round`, etc. from `entry.data`, with a fallback to the top level so a
  flattened entry still renders.
  - Note: the current `extractDebugLogs` in `src/commands.ts` reads `entry.ts`
    (which does not exist — it is `entry.data.ts`), so the "shows debug entries"
    path currently renders `?` timestamps. Fix this in the same change while the
    extraction logic is being touched — it is the same one-line class of bug.
- **Format per line**, mirroring the bash script's spirit (same fields, so muscle
  memory transfers):
  - `loop-event` → `[<ts>] [event/<category>] <msg>`
  - `loop-state` → `[<ts>] [state] phase=<phase> round=<round>`
  - `loop-refusal` → `[<ts>] [refusal] <phase>: blocked write to <path>`
  - `loop-dispute` / `loop-negotiate` → action/claim/text truncated to 80 chars
  - `loop-debug` → `[<ts>] [debug] <msg>`
  - fallback → `[<ts>] [<customType>] <compact JSON of data>`
  - `ts` = ISO-8601; if absent, `-`.
- **Order:** as provided by `getEntries()` (chronological). Do not re-sort.
- **No cap in v1.** The excerpt is evidence for the Tester/Writer agents, not a
  terminal dump. If a real session makes the file unusably large, revisit with a
  limit — that is easy to add later, and v1 stays simple.

## Scope — docs (required, per repo convention)

A new flag on a public command changes the user-facing contract. Per
`internal/README.md`, this is user-facing behavior: **README.md and SPEC.md are
updated in the same change**, not after.

- `README.md` — Commands table: document `--log-bug <name>` on the `/loop-debug`
  row (or a dedicated sub-section under Commands) + 2–3 sentence explanation.
- `SPEC.md` — add the flag to the command documentation with the same form /
  output-file contract as above.
- `internal/README.md` — move this item from Active to Done (rename file to
  `done-log-bug-spec.md`) when implemented and verified.

Explicitly **not** in scope:

- No new top-level command (flag on `/loop-debug`, not `/session-stat` or similar).
- No output-path flag — the file goes to `ctx.cwd`; moving it (e.g. into `internal/`)
  is a user step. An out-path flag would be born of one dogfooding workflow.
- No changes to `scripts/extract-session.sh`.
- No automatic agent turn / prompt injection from the command — it writes a file and
  notifies; nothing more.

## Implementation plan

1. **`src/commands.ts` — extend `cmdDebug`.** Accept `state` (already available at
   the call site in `index.ts`; the factory currently ignores it) so Context can read
   `state.current`. Parse `--log-bug <name>` / `--log-bug=<name>` out of `args`
   (small local parse, consistent with `parseLoopArgs`; do not grow that helper with
   loop-debug-only concerns).
2. **New pure helpers** (testable without the extension): `slugBugName(name)`,
   `extractLoopLogs(entries)` → `string[]`, `renderBugSpec({name, slug, state, lines, now})`
   → markdown string, `writeBugSpec(cwd, slug, markdown)` → `{ ok, path?, error? }`
   (exists-check, then write). Put them where `selectors.ts` helpers live or in
   `src/bug-spec.ts` if the file would bloat.
3. **Handler flow:** parse → slugify (empty → usage notify) → build lines from
   `ctx.sessionManager.getEntries()` → render → write → notify (success: path + next
   step; collision/error: notify error).
4. **Fix the `entry.ts` → `entry.data.ts` read** in `extractDebugLogs` (same change).
5. **Docs:** README.md, SPEC.md (see Scope above).

## Acceptance criteria

1. `/loop-debug --log-bug "Frozen at Phase B Step 5"` in a session that contains
   loop events writes `bug-fix-frozen-at-phase-b-step-5.md` to `ctx.cwd` containing:
   the title with the original name, a Context line with the current
   phase/round/spec/language, non-empty Log excerpt lines in the documented format,
   and placeholder prompts for Observed problem / Proposed fix / Acceptance.
2. `/loop bug-fix-frozen-at-phase-b-step-5.md` is accepted by the loop as a spec
   (file exists, readable, Phase 0 runs against it).
3. Re-running the same `--log-bug <name>` with the file present → error notify,
   file untouched.
4. `--log-bug` with empty name → usage notify, no file.
5. Session with no loop events → file written with the
   `(no loop events found in this session)` line.
6. `/loop-debug` with no args → identical behavior to today (last 20 entries,
   correct timestamps after the `data.ts` fix).
7. Works when the loop is idle (no active loop) — Context says "no active loop".
8. README.md and SPEC.md document the flag before the change is considered done.

## Tests

Follow the existing `test/extension.test.ts` patterns (`buildTestAPI`, `findCommand`,
seeded `_mockEntries`, mocked `ctx.cwd`). New/updated cases:

- `slugBugName`: spaces, case, punctuation, empty, already-slugged, emoji → stripped.
- `extractLoopLogs`: each of the seven `customType`s renders per the documented
  format; non-custom and unknown `customType` entries are excluded; nested
  `data` vs. top-level field fallback; missing `ts` → `-`; chronological order kept.
- `renderBugSpec`: contains all sections; original name in title; "no active loop"
  when phase is idle; no-events line when lines is empty.
- `writeBugSpec`: writes to `cwd/bug-fix-<slug>.md`; existing file → `{ ok: false,
  error }` and file content unchanged. Use a temp dir for `cwd` in these tests.
- Command-level: success notify includes path + `/loop` next step; collision notify;
  usage notify on empty name; no-args path unchanged; `--log-bug=name` equals form
  behaves identically to space form.

## Out of scope / deferred

- Limiting excerpt length (revisit only if a real session makes it a problem).
- Inspecting **past** session files from the command (bash script remains the tool).
- Auto-filling Observed problem / Proposed fix from the conversation (would require
  agent-side generation; the placeholder + Phase 0 enforcement covers v1).
