# wire-dispute-review

## Problem

Verified current state as of writing:

- The Phase B dispute mechanism is a **binary with roles hardcoded into the text**. Filing: `handleBDisputePropose` (`src/tools.ts:108-125`) increments `disputeCount` (`:115`), then `triggerDisputeReview` (`src/tools.ts:165-175`) sets `awaitDisputeReview = true` (`:170`) and returns the tool text `"Dispute filed. STOP producing tool calls. The Tester will review and respond."` (`:173`) — asserting the reviewer is the Tester no matter who filed. The block rule echoes it: `DISPUTE_REVIEW_REASON` = `"Dispute filed. Waiting for Tester review. STOP producing tool calls."` (`src/events/tool-call.ts:49-50`, used at `:72`).
- The **only** prompt that routes a dispute to anyone is `GP.promptWriterDispute(claim)` (`src/generic-prompts.ts:52-62`, verbatim: *"Tests still fail. You filed this dispute: … Use negotiate_review to proceed: - decision='approve' → escalate: you insist the test is wrong, Tester must fix it - decision='I will fix my code' → concede: … Do not write files. Call negotiate_review now."*), and it is sent **only from `applyRetryEffect`** (`src/events/agent-settled/effect-applicator.ts:85-91`) — i.e. only when the gate **fails**. A gate **pass** with a pending review schedules no one.
- The settle handler never schedules a review: `handleDisputeReview` (`src/events/agent-settled/dispute.ts:41-53`) logs `"Dispute review pending"` (`:49`), appends a `loop-state` entry, sets status, and returns `handled: false` unconditionally — the dispatcher step 6 is a documented dead guard (`src/events/agent-settled/index.ts:93`). Its comment states the invariant this spec breaks: *"only the retry effect clears it"* (`dispute.ts:48`).
- Runtime evidence (session `01a00dba-1766-7742-9327-f4a6cd3d225a`, 2026-08-17; artifact: the session JSONL + the repo as left behind): at 06:31:12 the **Tester** filed dispute #2 via `negotiate_propose` — a turn report ending with one Writer-file violation it is barred from fixing (`src/bug-spec.ts:21` prose comment failing the run spec's Acceptance #5 sweep). The 06:32:05 settle logged "Dispute review pending" and fell through to the gate; the gate **passed** (06:32:20) and the loop advanced to Phase C. **No review was ever scheduled or performed.** The loop ended `done` at 06:46:35 with the violation still present — verified against the live repo: `rg -n "loop-gate" src/bug-spec.ts` → line 21 matches, so the sweep `rg -n "loop-gate" src/bug-spec.ts` → 0 matches (Acceptance #5 of `internal/log-bug-spec.md:222`) is red in the finished state.
- A third defect on the same path: `executeBDisputeDefend` (`src/tools.ts:308-321`) delivers its handoff via `sendContextMessage` (`:319`, which is `pi.sendUserMessage` from **tool context** — the context proven to silently drop messages; spec 07, session `01a00b11`). It also increments `round` (`:316`) and records the decision nowhere in state.

Gap: a dispute filed by the Tester (the only channel for a fix-report carrying residual Writer-file issues) has no consumer; the gate can pass over a pending review; and the defend handoff, when it does fire, is delivered from a context that drops it.

## Target

The dispute review round is wired like the negotiate round (spec 07): filing tools record intent in state and send **no** handoff message; the settle handler delivers the role-correct review prompt from the agent-settled context (the only context proven to deliver); the review decision is routed by filer role, stored in state, and delivered by the settle handler; and the flag is cleared the moment the review is scheduled, so it never survives a settle. All four decision cells (filer × approve/defend) are closed and pinned. The role-fied text ("The Tester will review") is replaced with role-neutral text; the reviewer is determined from state, not assumed.

`LoopState` additions — three optional fields, spec 07 precedent (`negotiateProposed?` / `negotiateFeedback?`, `src/types.ts:32-33`):

export function promptTesterReviewWriterDispute(claim: string): string {
  return `TESTER (dispute review). The Writer disputed a test:

${claim}

Use negotiate_review to proceed:
  - decision='approve' → you concede: the test is wrong; you will fix it
  - decision='<your rebuttal>' → you defend the test; the Writer must fix the code

Do not write files. Call negotiate_review now.`;
}

export function promptWriterDisputeReview(claim: string): string {
  return `WRITER (dispute review). The Tester reported:

${claim}

Use negotiate_review to proceed:
  - decision='approve' → you accept the findings; you will fix the flagged file(s)
  - decision='<your rebuttal>' → you defend your implementation; the report is rejected

Do not write files. Call negotiate_review now.`;
}

export function promptWriterConcedeFix(claim: string): string {
  return `WRITER (dispute fix). You accepted the Tester's report:

${claim}

Fix the flagged file(s) to resolve it. Write source files only.
When done, stop producing tool calls.`;
}

export function promptTesterReportRejected(decision: string): string {
  return `TESTER (dispute). Your report was rejected. The Writer's defense:

${decision}

Verify the defense against the spec and the code, then continue Phase B.
When done, stop producing tool calls.`;
}

Quirks & known limitations (do not fix in this unit):
1. `handleBDisputeReview`'s debug text conflates roles — the Writer-filer's own decision logs as `"Dispute review: conceded"` (`src/tools.ts:246`); the "conceded" is the decision, not a role. Kept.
2. `accumulateDispute` (`src/metrics.ts:127-136`) has **zero production callers** (verified: `rg -n "accumulateDispute(" src/` → only the definition); the dispute metrics fields are never incremented in a live run. Out of scope; not fixed.
3. `handleBDisputePropose` counts Tester-filed reports against the same `maxDispute` budget as Writer disputes (`src/tools.ts:119-121`); the escalation text `"Dispute limit reached. Escalating to human."` (`src/tools.ts:382`) is role-neutral already. Kept.
4. On the `maxDispute` escalation path, `handleBDisputePropose` returns `"Proposal recorded. Awaiting review."` (`buildProposeResult`, `src/tools.ts:22-25`) even though no review will be requested. Kept.
5. Reviewer non-compliance is not re-prompted: if the reviewer settles the review turn without calling `negotiate_review`, no flag is set (it was cleared at scheduling), so the next settle runs the gate and the pending review evaporates with no consumer. The negotiate round has a reprompt mechanism for this (spec 07); disputes do not. Contained by the always-on turn-loop bound (`maxTurnsPerPhase` → escalation). A dispute reprompt is a separate unit — flagged, not hidden.
6. A rejected report cannot be re-disputed by the Tester: `promptTesterReportRejected` deliberately omits the re-dispute option (N1) — at that moment `disputeMode` is false, so a Tester filing is classified as Writer-filed by the pinned derivation and self-reviewed. The Tester's legitimate move is to verify the defense (read + run tests; no writes — rule 6) and stop; the gate then resumes Writer-driven implementation. The residual escalation channel is `maxDispute` → human. **No actor identity exists in state** — if one is added, this prompt can regain the re-dispute option. The asymmetry with `promptWriterDisputeDefended` (kept: "or file a new dispute with a different decision") is **principled**, not accidental: a Writer filing with `disputeMode: false` classifies correctly as Writer-filed and routes to the Tester — Writer filings cannot be misclassified, Tester filings can.

Intended shifts (accepted side effects, before → after):
1. The Writer-filer cell's routing prompt changes from the filer-addressed `GP.promptWriterDispute` (deleted, F-C) to the reviewer-addressed `GP.promptTesterReviewWriterDispute`, fired from the settle handler on the **filing** turn's settle (before: `promptWriterDispute` fired only from the retry effect when the gate failed). A dispute whose gate passes is now reviewed instead of evaporating.
2. The Tester-filer direction becomes live: before, filing by the Tester set a flag with no consumer (the 01a00dba hole); after, it schedules a Writer review (Table 1) and the approve/defend cells route to the new handlers (Tables 2-3).
3. `applyRetryEffect` loses its dispute branch (Inventory) — retry behavior for gate-fails is otherwise byte-identical.
4. Rule 2's window shrinks from "until the retry effect clears the flag" (could span phase boundaries) to "until the filing turn settles" — the block can no longer poison a later phase. This is the direct fix for the Phase C no-op turn in session 01a00dba.
